## 4. Core conceptual result

There is a useful common selector concept shared by the two projects, but its output type differs.

Define a project-relative selector problem by:

- a predeclared alternative domain `X`;
- a physically significant selection codomain `Y`;
- a source/grammar-bound mechanism `S`;
- a map or law

`S : X -> Y`

or, where stochastic selection is intended,

`K : X -> Prob(Y)`.

A mechanism crosses the shared selector frontier only if the selectivity is endogenous, noncircular, representation-resistant at claimed scope, physically meaningful, and not supplied by an uncharged auxiliary law.

This common form is not sufficient by itself for either project. Each project adds distinct output and coherence requirements.

## 5. Required distinctions

The preregistered distinctions remain necessary:

`ADMISSIBILITY` != `EXCLUSION` != `CANONICALIZATION` != `DYNAMICS` != `POSSIBILITY_SELECTION` != `HISTORY_ACTUALIZATION` != `EMPIRICAL_INSTANTIATION`.

Canonical evidence in both projects demonstrates why these distinctions matter:

- NFC SCC can classify/canonicalize histories without actualizing one;
- PGH-GRAM-0010 can exclude formal response distributions without choosing a local response law or actual physical instantiation;
- PGH's bridge can establish semantic contact while preserving multiple incompatible response laws.

### C1 — Domain independence

NFC: admissible histories/structures must be defined independently of which one is later declared actual; otherwise actualization is encoded into the domain.

PGH: well-formed grammar outputs/model class must exist before physical possibility is selected; target-specific construction is explicitly quarantined.

Disposition: genuinely shared.

### C2 — Nontrivial selectivity

NFC: an actualization mechanism must choose/weight among remaining admissible histories, not merely classify them.

PGH: Strong PGH requires substantive exclusion/possibility restriction; a grammar compatible with everything performs no physical selection.

Disposition: genuinely shared.

### C3 — Endogeneity

NFC: the accepted source audit fails universal actualization precisely because multiple selector extensions remain possible and no one selector is source-forced.

PGH: PGH-H0 remains live if an independent `L` performs substantive selection; strong PGH requires the relevant selection burden to arise from grammar rather than auxiliary law.

Disposition: genuinely shared.

### C4 — Noncircularity

NFC: selector hypotheses cannot assume the desired actual history or equivalent choice rule.

PGH: target law cannot be hidden in topology, semantics, scope, interpretation, or grammar primitives and then counted as derived.

Disposition: genuinely shared.

### C5 — Representation invariance

NFC: canonical source/branch structure is formulated relative to source equivalence/isomorphism and branch-visible observables; an actualization law with only presentation-dependent force would not be source-canonical.

PGH: representation invariance is an explicit Strong-PGH requirement; mere renaming of PGH-GRAM-0010 is not candidate change.

Disposition: genuinely shared, although PGH states the cross-language burden more aggressively.

### C6 — Semantic physical force

NFC: carrier uniqueness or structural classification is insufficient; actualization must have physical-history force.

PGH: formal equivalence/exclusion alone is not enough to establish physical equivalence/possibility without a qualified semantic/physical bridge.

Disposition: genuinely shared.

### C7 — Provenance visibility

NFC: Book V hidden-channel exclusion requires load-bearing branch structure/hypotheses to be declared.

PGH: topology, scope, semantics, or other selectively active inputs must be charged explicitly; relocation does not count as explanation.

Disposition: genuinely shared, with PGH imposing the stronger explanatory accounting standard.

### C8 — Multiplicity resolution

NFC: the unresolved multiplicity is among admissible histories/history classes.

PGH: the unresolved multiplicity is between merely well-formed structures and structures that are physically possible without an independent `L`.

Disposition: shared only in abstract selector form. The relevant multiplicity is project-specific. This criterion marks the boundary at which the common core begins to bifurcate.

| N5 | TEMPORAL_OR_GLOBAL_COHERENCE | REQUIRED FOR GLOBAL-HISTORY CLAIM |

### N1 — History-level domain

This is the first irreducible NFC-specific requirement. The accepted missing object is not merely a classifier over structures. It must act on admissible histories or history equivalence classes if it is to answer the actual-history question.

### N2 — Dynamic compatibility

A proposed selector cannot contradict the dynamics/transition structure whose histories it is supposed to actualize. Branch-local dynamics may therefore be inputs to a scoped selector, but existence of dynamics alone is not actualization.

### N3 — Branch/source compatibility

A universal NFC selector must not silently privilege one branch-specific realization unless that privilege is source-forced. This is where the prior conservative-extension/nonforcing result is load-bearing.

### N4 — Stochastic normalization

If actualization is probabilistic, weights must form a well-defined normalized law/kernel over the relevant history domain; informal preference or defect ranking is insufficient.

### N5 — Temporal/global coherence

If the claim is one global actual history, local selection decisions must compose consistently into that history rather than define incompatible local actualizations.

## 8. PGH-specific extension matrix P1–P5

| ID | Requirement | Status |
|---|---|---|
| P1 | GENERATIVE_COMPRESSION | REQUIRED BY STRONG PGH |
| P2 | LAW_EXHAUSTION | REQUIRED BY STRONG PGH |

| P4 | POSSIBILITY_LEVEL_SUFFICIENCY | REQUIRED / DEFINING SCOPE |
| P5 | FAILURE_EXPOSURE | REQUIRED BY PROGRAM STANDARD |

### P1 — Generative compression

Strong PGH requires a compact grammar rather than an extensional list of possibilities. This has no direct NFC actualization analogue.

### P2 — Law exhaustion

Strong PGH fails if an independent substantive `L` remains necessary after grammar is specified. This is stronger than merely demanding that an actualization rule be declared.

### P3 — Grammar/bridge separation

A semantic bridge may establish physical reference/contact, but it cannot secretly perform the substantive physical selection attributed to grammar. `PGH-OBJ-0051` is intentionally full-class and law-free in this sense.

### P4 — Possibility-level sufficiency

Strong PGH does **not** require selection of one actual universe/history. It requires grammar to determine substantive physical possibility at claimed scope without independent law doing that work.

This is the first irreducible PGH-specific requirement and the main divergence from NFC.

### P5 — Failure exposure

A PGH candidate must risk an independently testable prohibition/counterexample. PGH-OBJ-0052 is designed prospectively around this standard even though no positive empirical credit exists.

## 9. First irreducible NFC ↔ PGH divergence

with physical actualization force.

`S_PGH : W(G)/~ -> P_physical`

where the Strong-PGH burden is that `S_PGH` be constituted by grammar/qualified bridge structure without an independent substantive `L`.

The problem is: which well-formed structures/derivations correspond to physical possibility?

PGH does not, by this claim alone, require a further map

`P_physical -> one actual history`.

Therefore NFC actualization and PGH law exhaustion share selector architecture but answer different physical questions.

## 15. Why Outcome A is justified

Outcome A does not claim the two frontiers are identical.

It claims there is a nontrivial common selector core plus identifiable project-specific extensions. The criterion analysis supports exactly that structure:

- C1–C7 are directly shared;
- C8 is shared at an abstract multiplicity-resolution level but its domain/codomain are project-specific;
- NFC then requires N1–N5;
- PGH then requires P1–P5.

This is stronger and more useful than a loose analogy because it provides an explicit test harness for future candidate mechanisms in either project.

## 16. Scientific consequence

The two projects should not search for the same final object.

They can, however, share a **selector-audit methodology**.

A future candidate in either project can first be tested against C1–C8, then against its project-specific extension set.

This yields a disciplined common vocabulary:

`FORMAL FAMILY -> NONTRIVIAL SELECTOR CORE -> PROJECT-SPECIFIC PHYSICAL CLAIM`

without conflating physical possibility with actual history.

## 17. Routing consequence

No source-project mutation is justified.

The highest-information next operation is to use the new selector-core test harness to screen **candidate sources of endogenous selectivity**, but only where source material already exists. For NFC, this means identifying the smallest additional axiom/law class that would satisfy N1–N5 without contradicting source nonforcing. For PGH, it means identifying what would be required for PGH-GRAM-0010's formal exclusion to acquire C6/P2 physical law-exhaustion force without smuggling topology/source independence as unexplained physical law.

Those should remain separate project-specific studies despite sharing C1–C8.
